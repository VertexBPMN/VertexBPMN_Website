Git-Plugin

Vom Editor
zum Pull Request.

Der Git-Arbeitsbereich ist direkt in den BPMN-Editor integriert. Repositorybindungen, freigegebene Modellverzeichnisse und explizite Berechtigungen legen fest, wer welche Modelle bearbeiten darf.

01

Öffnen und vergleichen

Repository und Branch auswählen, eine BPMN-Datei aus einem konkreten Commit laden und im vorhandenen Editor bearbeiten. Vergleich und Git-Historie machen Änderungen nachvollziehbar.

02

Commit und Push

Den bestätigten Editorstand mit einer Nachricht auf einem Arbeitsbranch committen. Anschließend genau diesen Commit pushen. Persistente Aufträge zeigen den Fortschritt und das Ergebnis.

03

Pull Requests verfolgen

Aus einem bestätigten Push einen GitHub-PR erstellen. Gespeicherte PR-Belege wieder öffnen und den aktuellen Zustand, tatsächlichen Mergecommit und die Reviewhistorie gesondert abfragen.

Die Git-Oberfläche ist derzeit auf BPMN-Dateien ausgerichtet. Ein angezeigtes Review oder ein Merge ist keine Deploymentfreigabe; der Arbeitsbereich führt keinen automatischen Merge oder Runtime-Deploymentablauf aus.

So arbeiten Sie damit

Ein klarer Ablauf.

  1. Verbinden: Im BPMN-Editor „Git model workspace“ öffnen, Repository, Branch und Modellverzeichnis auswählen.
  2. Bearbeiten: Die Datei mit „Open in existing BPMN editor“ laden. Änderungen vornehmen, Snapshot vergleichen und Historie prüfen.
  3. Versionieren: Commit-Nachricht eingeben und den bestätigten Editorstand committen. Auf den erfolgreichen Auftragsstatus warten, dann den bestätigten Commit pushen.
  4. Zusammenarbeiten: Zielbranch, Titel und Beschreibung wählen und einen Pull Request erstellen. Den PR auf GitHub prüfen und seinen aktuellen Status im Studio abfragen.

Das Beenden des Wartens im Studio stoppt bereits angenommene Aufträge nicht. Ein gespeicherter eigener PR-Beleg lässt sich nach einem Neustart über seine Operation-ID wieder öffnen.

Voraussetzungen

Die Integration ist standardmäßig deaktiviert. Sie benötigt Git auf dem API-Host, ein geschütztes Workspace-Verzeichnis, explizite HTTPS-Hostfreigaben sowie passende Keycloak- und GitHub-App-Credentials. Die aktuelle Remote-Integration verwendet GitHub. Rollen und Repository-Grants werden serverseitig und tenantbezogen geprüft.

Das Git-Plugin ist eine integrierte Source-Control-Erweiterung und benötigt keine separat hochzuladende Plugin-DLL. Die Einrichtung erfolgt über SourceControl. Mit SourceControl:Enabled=false lässt sich die Integration deaktivieren und im Studio ausblenden; gespeicherte Daten werden nicht gelöscht.

Aktueller Abnahmestatus

Ausgewählte lokale Prüfungen und sichtbare Abläufe in einem isolierten GitHub-Testrepository sind dokumentiert: darunter PR-Erstellung, Wiederöffnung gespeicherter Belege und Live-Mergeabfrage. Die Reviewhistorie ist implementiert und durch Adaptertests geprüft; ihre sichtbare Studio-Abnahme ist noch offen.

Die vollständige Git-Abnahme bleibt offen, insbesondere für unabhängige Audit-/Reviewverifikation, reale verlorene Antworten und Rechteentzugsfälle sowie vollständige automatisierte HTTP-/UI-Regression und strengen Gesamtbuild. Daraus wird keine Produktionsfreigabe abgeleitet. Dokumentationsstand: 9. Oktober 2026.
